## Local operator export

The installed package offers native-runtime schema and the following local CLI:

    cadence-mcp-bridge native-runtime bundle --settings RUNTIME_JSON
      --context CONTEXT_ID --registration NATIVE_REGISTRATION_JSON
      --output NEW_LOCAL_DIRECTORY

Registration explicitly joins ADE/reader registrations and a compiler validation
request with source cell/state and named libraries for each design/analysis.
The request checks explicit numeric contracts; it is not submitted. Source paths
must be inside the registered workspace, outside protected vendor/runtime roots.
The receipt binds13 fixed assets plus a schema3 manifest and provider binding.
Export cannot confirm, install, activate or dispatch.

Native execution requires the registered normal user, fixed Python with isolated
startup/no bytecode, separate activation history/active pointer and no revocation.
The preflight-only updater cannot install this worker. Explicit native setup
CLI actions are stage, activate, inspect and revoke. All require --bundle and
--expected-manifest-sha256. Mutations also require --operator-authority naming
the actual human instruction; inspect accepts no authority argument. Local
code assets must match the installed package before any remote contact.
A separate fixed setup helper receives only that compiled hash allowlist.

Stage appends/reuses14 immutable files under the existing managed runtime root.
Activate performs a fresh fixed probe and appends history then the pointer under
the existing lock. A complete history with absent pointer is restartable; corrupt
partial files are preserved/rejected. An identical activation changes0. A different
already-active native runtime is rejected: replacement/upgrade is not implemented
by this initial setup CLI. Legacy/preflight controls and accounting are untouched.
Revoke appends a per-runtime history-bound record, retains the active pointer and
prevents that runtime from new admission; completed lookup remains possible.
This is operator provisioning, never an import/doctor/server side effect, MCP
grant writer, simulation approval or root operation. Actual setup validation is
still pending; do not fabricate records or use the preflight-only updater.

## Existing accounting and lifecycle

Public logical ledger reference shared-ledger maps to the unchanged internal
counter file. Historical file-path confirmations remain inspection-only.

The coordinator retains the existing run.lock throughout admission and detached
normal-user execution. It checks confirmed scope, source/model hashes, current
environment, policy and latest ledger before one reservation. DISPATCHED intent
is durable before fork. Accepted/ambiguous ID retries perform lookup only. Partial
records are preserved/rejected. Pending cancellation creates an absent-identity
tombstone or cancels RESERVED; never refunds or terminates active work. Lookup
verifies immutable reservation provenance without waiting for the worker lock.

The common worker copies owned OA/ADE, remaps only owned designInfo/projectDir,
uses the shared fixed renderer, verifies effective netlist input, runs Spectre
and extracts a bound frame. EXTRACTION_FAILED preserves PSF; simulation is never
automatically retried. Extraction-only recovery is pending. Planned input digest
and actual netlist SHA are separate; PSF and pre-receipt tree hashes are distinct.

Fixed argv/shell=False/private logs are used. Linux group cleanup retains the
unreaped leader against PID/PGID reuse and handles children after leader exit;
the lifetime lock remains until the group stops. No caller PID/shell/admin or
public termination capability. OA library/technology routing and whole driver
still need actual VM qualification.
